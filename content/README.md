# Documentation Hub

This folder turns the repository into a practical reference hub for developers building production apps with Next.js and Supabase.

## Sections

| Section                                                  | What It Covers                                                        |
| -------------------------------------------------------- | --------------------------------------------------------------------- |
| [Learning Paths](learning-paths/README.md)               | A 7-day plan and beginner-to-advanced roadmap.                        |
| [Starter Kits](starter-kits/README.md)                   | Starter ideas for SaaS, auth, Stripe, realtime, and admin dashboards. |
| [Open Source Examples](open-source-examples/README.md)   | Real GitHub projects using Next.js and Supabase.                      |
| [Symptom Reference](incidents/README.md)                 | Debugging reference grouped by area, with links to the fixing docs.   |
| [Production Checklists](production-checklists/README.md) | Auth, RLS, deployment, Stripe, performance, and security checks.      |
| [Snippets](snippets/README.md)                           | Reusable auth, middleware, RLS, and API helper snippets.              |
| [Debugging Playbook](debugging-playbook/README.md)       | Common production problems and how to debug them.                     |

## How To Use This Hub

Start with [Learning Paths](learning-paths/README.md) if you are new to the stack.

Use [Production Checklists](production-checklists/README.md) before shipping a real app.

Use [Debugging Playbook](debugging-playbook/README.md) when something breaks in auth, RLS, deployment, hydration, or API calls.

Use [Symptom Reference](incidents/README.md) when you know the symptom and need the likely root cause, fix, and verification step quickly. For the numbered incident catalog that maps each failure to a reusable repo asset, see the [Production Incident Index](../reference/incident-index/README.md).

Use [Open Source Examples](open-source-examples/README.md) when you want to study real implementations instead of isolated snippets.
